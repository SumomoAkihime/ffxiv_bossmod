# 上游同步说明

本仓以 Reborn 机制数据为主体，配合少量 awgil 调度与移动兼容适配，并保留经过回放或实机确认的本地雷达增强。同步时按 GroupType、GroupID、NameID 和主 OID 核对身份，不能按 CE 编号、文件名或目录名直接判断同一模块；旧编号与新编号相同身份时只保留一份，避免重复注册和激活。`CriticalEngagement` 的 `NameID` 是 `DynamicEvent` 行字段，不直接等同实体的 BNpcName `NameID`。

本地实测与自建雷达保护项见 [sync/local-radars.json](../sync/local-radars.json)。该清单是确认项；新发现的本地差异必须人工审查，不能因为上游标为 `Contributed` 就整文件覆盖。核心层跟随 Reborn 并重放必要补丁，按混合架构逐项适配与验证，不按上游目录批量覆盖；`ActionQueue`、`Autorotation`、`BossModule`、`Framework`、导航及动作常量等文件需要单独检查。

编号提醒：根记录所称 CE208（OID `0x4C4F`）在当前源码中对应 `CE201ABeastUnleashed.cs`；`CE208FamiliarTactics.cs` 是另一组 GroupType/主 OID 的 Reborn 模块。清单中 `GroupType=CriticalEngagement` 条目的 NameID 按 `DynamicEvent` 语义记录，实体 NameID 需以回放或游戏数据另行核对。

魔之塔普通/高难 Boss4 共用 `IndexArenaBounds`，同步场地几何时要保留真实材质顶点，并检查障碍图 BMP 文件头为 `BM`、`maplist.json` 没有悬空引用。已验证的 A16 边界中心分离、魔之塔导航空 `ShapeDistance` 防护和 D093 旋转提示修复属于支撑性保护项，不能被上游同段代码覆盖，除非上游已有明确等价修复。

本说明描述同步原则和保护范围，不表示目标 Reborn 提交已经全部合并完成；每轮同步仍需由 Lead 记录实际应用、跳过和待审查项。

## 已落地的循环与移动边界

职业输出和移动按实际启用模块运行，不再依赖 `VBM AI` 这个显示名称。多个移动模块同时启用时，以预设选中顺序、再以预设内模块顺序确定第一个；第一个选择 `None` 或因热病等状态停止时，后续移动模块和旧 AI 均不补上旧路径。职业模块仍按顺序全部运行。

手动 AI 跟随仍可使用：原版移动模块存在时，跟随只提供目标，由原版统一避险；未运行原版移动模块时，旧 AI 负责手动跟随。切换/暂停/销毁时清理遗留目标，并丢弃旧异步结果。`ForbidMovement` 和坐骑限制同样约束原版移动；总停止状态不会被旧 AI 清除。

原版 `Presets.*`、临时策略及外部启停接口属于兼容边界。AutoDuty 等调用方需要明确控制预设时，保持原版 IPC 契约；“旧 AI 不覆盖职业预设”不等于禁止外部插件显式选择预设。现有多预设接口和插件身份保留。

## 每轮同步

1. 读取 [reborn.json](../sync/reborn.json) 的准确来源、已整合批次与待办；本轮记录不表示和上游整树一致。
2. 同步前保存自建雷达快照，例如 `python tools/check_local_radars.py --snapshot C:/Temp/local-radars-before.json`。也可通过 `--revision <提交>` 从 Git 基线生成快照。
3. 对照 Reborn 最终树分批适配，逐项重放已记录的必要补丁；同身份上游 WIP/占位不得替换本地可用雷达。上游已有完成实现时采用上游数据，同时审查并保留仍需要的本地增强。
4. 同步后执行 `python tools/check_local_radars.py --compare C:/Temp/local-radars-before.json`。工具只比较清单内 `.cs`，统一检出换行后计算摘要，不读取或修改用户制作记录。差异返回非零，须审核是授权 API 适配还是意外机制覆盖；目录改名也须核对身份后更新清单。
5. 核心变更通过 Release 构建及 [循环/移动回归](../Tests/RotationMovement/README.md)；几何支撑变更运行 [多边形回归](../Tests/PolygonQueries/README.md)。按实际受影响模块补充离线检查，实机集中测试循环＋移动、启停与外部联动组合。
6. 更新本轮来源和例外记录，提交测试分支。正式升版、ZIP 和双仓发布单独执行。

## 外部插件兼容范围

以 awgil `v7.5.6.4 / 0b741f5fa` 核对 IPC，补齐 `Configuration.DisableModule`、`Presets.Activate`、`Presets.Deactivate`。`Configuration` 接受 `IReadOnlyList<string>`；模块禁用按原版语义影响后续模块创建，不强制卸载正在运行的战斗模块。`AI.NaviTargetPos/IsNavigating` 已识别当前移动负责方，原版停止时不报告旧 AI 目标。

AutoDuty 对照官方 [53f4e7400](https://github.com/ffxivcode/AutoDuty/tree/53f4e7400f9791f4534f803a2ec2d2ff709375ba) 的 `AutoDuty/IPC/IPCSubscriber.cs`、`AutoDuty/AutoDuty.cs` 和两份 `AutoDuty/Resources` 预设。其预设由调用方创建，不需要塞入本仓默认预设；所需 31 种模块类型均保留，两份实际 JSON 已通过导入及策略完整性检查。AutoDuty 通过 `Presets.SetActive` 独占选择其预设，再用 NormalMovement 的 `Destination=Pathfind/None` 临时覆盖切换战斗和路径移动。若手动追加其他移动预设，仍按第一移动模块规则；不要把 AutoDuty 预设放在另一个移动模块之后却期望临时策略控制前者。

vnavmesh 正在运行路径时，现有 `MovementOverride.FollowPathActive()` 通过 `vnav.PathIsRunning` 让出移动注入，继续保留。Reborn 附加的 `AI.SetPreset/GetPreset` 并非 awgil 接口；此次核对的 AutoDuty 主路径不调用它们，仍保留现有空兼容入口，不恢复旧 AI 自动覆盖职业预设的行为。

## 辅助职业同步范围

已接入 Reborn `20b8092f4` 的盗窃、辅助忍者、白魔法师、黑魔法师、召唤师、青魔法师、赤魔法师自动化及动作/状态定义。辅助职业模块仍保留上游 WIP 质量标记；“已同步”不表示所有辅助职业的每个技能都自动施放。辅助亡灵法师仅有动作定义，上游尚无自动循环分支；魔蛙变、前踏步等也不新增自动施放。盗窃和辅助白魔复活默认关闭，其他新增输出与自疗选项采用上游默认值，并受装备技能和对应条件限制。

本地适配保留多预设所需的 `ref Actor?` 接口、普通赤魔 Dualcast 与近战连段保护、魔跳跃的危险区域禁止；前踏步注册位移检查时映射为本地 `ForbidExecute`。魔震雷与雷暴均按雷弱点调整优先级，不能覆盖回上游的火/风判断。召唤法术保留 4 秒读条且不被即刻咏唱清零。详见 [辅助职业离线回归](../Tests/SupportJobs/README.md)。
